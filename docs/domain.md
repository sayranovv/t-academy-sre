# Предметная область и требования v1

Дата: 2026-09-28. Тема и требования курса заданы пользователем. Детали MVP ниже —
проектные допущения, которые можно пересмотреть до реализации. Интервью и исследования
пользователей не проводились.

## Цель и участники

Ответственный видит, какие устройства есть, что можно выдать, у кого находится
конкретный экземпляр и какова история его выдач. Приложение учитывает передачи,
но не подтверждает физическое наличие и не заменяет акты материальной ответственности.

Оператор — IT-специалист или другой ответственный. Сотрудник — получатель, без входа
в приложение. Одна организация и общий фонд оборудования; местоположения не учитываются.

## Словарь

| Термин | Значение | Пример |
|---|---|---|
| Категория | Группа моделей | Ноутбук |
| Модель | Разновидность устройства | Производитель Example, Laptop 14 |
| Экземпляр | Физическая единица | Инвентарный номер EQ-0001 |
| Сотрудник | Получатель с табельным номером | EMP-001, Иван Петров |
| Выдача | Период ответственности за экземпляр | Выдан 28 сентября, не возвращён |
| Открытая выдача | Выдача без времени возврата | `returned_at IS NULL` |
| Доступно | `usable` без открытой выдачи | Можно выдать |
| Недоступно | Временно исключено из выдачи | Требуется проверка |
| Списано | Окончательно исключено из оборота | Без бухгалтерских расчётов |

Десять одинаковых ноутбуков — одна модель и десять экземпляров. Производитель —
текстовый атрибут модели; его адреса и контакты в MVP не учитываются.

## Границы MVP

Включены CRUD категорий, моделей, сотрудников и экземпляров; выдача, возврат,
история, поиск и фильтры. Сотруднику можно выдать несколько устройств.
У экземпляра много выдач в истории, но максимум одна открытая.

Исключены авторизация/роли, стоимость и амортизация, закупки, поставщики, расходники,
ремонты как отдельный процесс, резервирование, заявки, подразделения, местоположения,
файлы, штрихкоды, массовый импорт, уведомления и интеграции.
Временная недоступность — состояние, а не система управления ремонтами.

## Бизнес-правила

| ID | Правило |
|---|---|
| BR-01 | Инвентарный номер уникален и обязателен; серийный номер необязателен и не глобально уникален |
| BR-02 | Табельный номер уникален; ФИО не уникально; email необязателен и не идентификатор |
| BR-03 | Выдавать можно только `usable` без открытой выдачи активному сотруднику |
| BR-04 | Выдача и возврат атомарны; конкурентные операции не нарушают BR-03 |
| BR-05 | Получатель, экземпляр и время выдачи неизменяемы; закрытая выдача не открывается повторно |
| BR-06 | Повторный возврат конкретной выдачи возвращает её состояние, не меняя время |
| BR-07 | Передача другому сотруднику — возврат и новая выдача; отдельной атомарной передачи нет |
| BR-08 | Деактивация сотрудника запрещена при открытых выдачах |
| BR-09 | Переход в `unavailable` или `retired` запрещён при открытой выдаче |
| BR-10 | `unavailable` можно вернуть в `usable`; `retired` — конечное состояние |
| BR-11 | DELETE разрешён только без зависимых записей; выдачи не удаляются |
| BR-12 | Удаление ошибочной неиспользованной карточки и списание использованного устройства различаются |
| BR-13 | Времена выдачи/возврата устанавливает сервер после блокировок; задние даты исключены |
| BR-14 | Переименование сотрудника или модели меняет отображение старой истории; исторических снимков нет |
| BR-15 | Модель экземпляра нельзя менять после первой выдачи; описательные поля можно исправлять |

История выдач — не полный аудит изменений. Ошибочную выдачу исправляют возвратом
и новой выдачей, с пояснением в примечании. Уничтожение записи не предусмотрено.

## Сценарии

1. **Завести оборудование:** выбрать или создать категорию и модель, добавить экземпляр
   с инвентарным номером. Начальное состояние `usable`, выдач нет.
2. **Добавить сотрудника:** табельный номер и ФИО; по умолчанию активен.
3. **Выдать:** выбрать доступное устройство и активного сотрудника, добавить примечание.
   После сохранения показать получателя и время выдачи.
4. **Вернуть:** подтвердить возврат конкретной открытой выдачи. Устройство доступно снова.
   Если оно неисправно, отдельным действием сделать недоступным. Между действиями
   возможна другая выдача — тогда смена состояния отклоняется. Атомарный возврат
   неисправного устройства — возможное расширение, не обещание MVP.
5. **Посмотреть историю:** карточка сотрудника или устройства показывает выдачи от новых
   к старым, с устройством, получателем и датами.
6. **Вывести из оборота:** вернуть открытые выдачи, затем списать устройство или
   деактивировать сотрудника; сохранить историю.
7. **Исправить карточку:** изменить разрешённые поля или удалить без зависимостей.
   При конфликте объяснить причину и следующий шаг.

## Экраны

| Экран | Содержание и действия |
|---|---|
| Оборудование | Номер, модель, категория, состояние, доступность, получатель; поиск по номеру/серийному номеру/модели; фильтры категории, состояния и доступности |
| Карточка оборудования | Данные, редактирование, выдача/возврат, смена состояния, история |
| Сотрудники | Поиск по ФИО/табельному номеру; фильтр активности; создание и изменение |
| Карточка сотрудника | Текущие устройства, история, активация/деактивация, допустимое удаление |
| Справочники | Категории и модели: таблицы и формы CRUD |

Dashboard и отдельный экран всех выдач не обязательны. Язык UI — русский, основное
использование — desktop-браузер. Реализованный визуальный язык описан в
[design-system.md](design-system.md).
Таблицы имеют пагинацию, состояния загрузки, ошибки и пустого результата.
Формы сохраняют ввод при ошибке; кнопка сохранения блокируется на время запроса.
После конфликта показать объяснение и обновить карточку. После сетевого тайм-аута
выдачу автоматически не повторять: перечитать карточку и выяснить результат операции.
Удаление и списание требуют подтверждения; отмена формы не меняет данные.
Поля имеют подписи, интерфейс доступен с клавиатуры, цвет не единственный индикатор.
Даты показывать в часовом поясе браузера с его обозначением.

## Критерии приёмки

| ID | Результат |
|---|---|
| AC-01 | Полный CRUD четырёх сущностей работает через UI и API, включая физическое удаление несвязанных записей |
| AC-02 | Дубликаты инвентарного/табельного номера и пустые обязательные поля отклоняются |
| AC-03 | Две одновременные выдачи одного устройства: одна успешна, другая получает конфликт; одна открытая запись в БД |
| AC-04 | Недоступное/списанное устройство или неактивный сотрудник не допускают выдачу |
| AC-05 | После возврата возможна новая выдача; повтор старого возврата не закрывает новую |
| AC-06 | Выдача против деактивации/списания не создаёт противоречивого состояния |
| AC-07 | Нельзя удалить сотрудника/устройство с историей, модель с экземплярами или категорию с моделями |
| AC-08 | Ошибка транзакции не оставляет частично изменённых данных |
| AC-09 | Перезапуск backend сохраняет данные; две реплики работают с общей БД |
| AC-10 | Поиск, фильтры, стабильная пагинация, пустые результаты и ошибки сети отображаются корректно |
| AC-11 | Неактивный сотрудник остаётся в истории и может быть активирован; списание необратимо |
| AC-12 | Выдачи одного устройства не пересекаются; закрытые выдачи не изменяются и не удаляются |

SLO, лимиты CPU/RAM и целевые объёмы определим после первого измерения.
Подтверждённых показателей latency/RPS или потребления памяти пока нет.
